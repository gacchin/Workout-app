## 1. 概要

本アプリは、**ブラウザだけで動くWebアプリ**です。サーバーやインストール作業は不要で、`index.html` をブラウザで開くと起動します。

| 区分 | 採用技術 |
|---|---|
| 画面の構成 | HTML5 |
| 見た目 | CSS3 |
| 処理 | JavaScript（フレームワークなし） |
| グラフ描画 | Chart.js 4.4.1 |
| データ保存 | localStorage（ブラウザの保存領域） |
| サーバー | なし |

## 2. 全体構成

```
利用者のPC
┌──────────────────────────────────────────┐
│ ブラウザ（Chrome / Edge など）                │
│                                          │
│  index.html … 画面の骨組み                   │
│  style.css  … 見た目・デザイン                │
│  app.js     … 入力・保存・グラフ・履歴の処理      │
│     │                                    │
│     ├─→ Chart.js（グラフ描画用ライブラリ）      │
│     └─→ localStorage（記録データの保存場所）    │
└──────────────────────────────────────────┘
          │
          └─ Chart.js の読み込みだけインターネットを使う
             （CDN: cdn.jsdelivr.net）
```

すべての処理がブラウザの中で完結し、記録データを外部に送ることはありません。

## 4. 各技術の役割

### 4.1 HTML（index.html）
画面に置く部品と、その並び順を決めます。

- 記録入力フォーム（日付、種目、重量、Rep数、メモ、保存ボタン）
- グラフ表示エリア（種目と重量の選択欄、グラフ）
- 履歴一覧

### 4.2 CSS（style.css）
見た目を決めます。

- 配色は CSS 変数（`:root`）でまとめて管理しています。メインカラーは `#e4572e`（オレンジ）です。
- 画面幅は最大 720px で、スマホでも見やすいレイアウトにしています。

### 4.3 JavaScript（app.js）
アプリの動きを担当します。主な処理は次のとおりです。

| 処理 | 関数 |
|---|---|
| データの読み込み・保存 | `loadRecords()` / `saveRecords()` / `loadExercises()` / `saveExercises()` |
| 登録済み種目の管理 | 種目登録フォーム / `renderRegisteredExercises()` |
| 記録の入力 | フォームの `submit` イベント |
| 種目の入力候補の作成 | `renderExerciseList()`（登録済み種目と過去の記録から作成） |
| グラフの種目・重量の選択欄の作成 | `renderGraphSelectors()` / `renderWeightSelector()` |
| グラフの描画 | `renderChart()` |
| 履歴の表示・削除 | `renderHistory()` |
| 画面全体の描き直し | `render()` |

### 4.4 Chart.js
グラフを描くための外部ライブラリです。

- バージョン: 4.4.1
- 読み込み元: `https://cdn.jsdelivr.net/npm/chart.js@4.4.1/dist/chart.umd.min.js`
- 使用するグラフ: 折れ線グラフ

### 4.5 localStorage
ブラウザに付いているデータの保存領域です。

- 保存キー: `workout-records`（記録）、`workout-exercises`（登録済み種目）
- 保存形式: 配列を JSON 文字列にしたもの（記録の項目は [仕様書](specification.md) の「データ項目」を参照）

## 5. 処理の流れ（記録を保存するとき）

```
1. 利用者が入力して「保存」を押す           … HTML
2. 入力内容を受け取り、記録を1件作る         … JavaScript
3. localStorage に保存する                  … localStorage
4. 種目の候補、グラフ、履歴を描き直す         … JavaScript + Chart.js
5. デザインを付けて画面に表示する            … CSS
```

## 6. 採用理由

| 判断 | 理由 |
|---|---|
| HTML / CSS / JavaScript のみで作る | 機能が少なく、フレームワークを使うとかえって複雑になるため |
| サーバーを置かない | 「自分だけが1台の端末で使う」用途なら、ブラウザへの保存で足りるため |
| Node.js を使わない | サーバーが不要で、開発するPCにも入っていなかったため |
| Chart.js を使う | グラフを一から作るより簡単で、広く使われていて情報も多いため |

## 7. 制約と注意点

### 7.1 データの保存について
データは**ブラウザごと**に保存されます。次の点に注意してください。

| 場面 | 影響 |
|---|---|
| 別のブラウザで開く（例: Chrome → Edge） | 記録が見えない |
| シークレットモード / InPrivate で開く | ウィンドウを閉じると記録が消える |
| ブラウザのプロフィールを切り替える | 記録が見えない |
| 閲覧データの削除で「サイトデータ」も消す | 記録が消える |
| アプリのフォルダを移動・名前変更する | ブラウザによっては記録が見えなくなる |
| 別のPCやスマホで開く | 記録が見えない |

**運用ルール**: 使うブラウザを1つに決め、通常のウィンドウで開き、フォルダは移動しないこと。

### 7.2 インターネット接続について
Chart.js をインターネットから読み込むため、**オフラインではグラフが表示されません**。記録の入力と履歴は、オフラインでも使えます。

## 8. 今後の拡張で必要になる技術

| やりたいこと | 追加する技術の例 |
|---|---|
| 記録のバックアップ・ブラウザ間の引っ越し | ファイルへの書き出し・読み込み機能（追加技術は不要） |
| オフラインでもグラフを表示する | Chart.js をプロジェクト内に保存して読み込む |
| PCとスマホで同じデータを使う | Supabase や Firebase（クラウドのデータベース） |
| ログイン機能 | Supabase Auth、Firebase Authentication |
| 画面や機能が大きく増える | Node.js + React / Next.js + TypeScript |
| スマホのホーム画面からアプリのように使う | PWA 化（manifest、Service Worker） |

## 9. 用語集

| 用語 | 意味 |
|---|---|
| フロントエンド | 画面側。ブラウザで動く部分 |
| バックエンド | サーバー側。データの保存や共有を担当する部分（本アプリにはない） |
| ライブラリ | 便利な機能をまとめた、借りて使える部品（例: Chart.js） |
| CDN | ライブラリなどをインターネット経由で配っている場所 |
| localStorage | ブラウザに付いているデータの保存場所 |
| JSON | データを文字で表すための書き方 |
| Node.js | JavaScript をブラウザの外で動かすためのソフト（本アプリでは未使用） |
